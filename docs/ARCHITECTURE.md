# معماری عمومی لریو

```text
Browser
  ├── Auth  — هویت، نشست و SSO
  ├── Blog  — محتوا و پروفایل
  ├── Chat  — پیام، گروه، کانال و فایل
  ├── Eco   — ابزارهای مکمل
  └── Time  — زمان و برنامه‌ریزی
```

هر سرویس مرز داده و API خودش را دارد. هویت بین سرویس‌ها با ادعای امضاشده منتقل
می‌شود. در Chat، نقش سراسری یا نام کاربری به‌تنهایی مجوز مدیریت گفتگو نیست.

در معماری هدف E2EE، لایهٔ Crypto Client قبل از API قرار می‌گیرد. API فقط envelope،
ciphertext، nonce، شناسهٔ کلید و metadata حداقلی را نگه می‌دارد. کلید خصوصی دستگاه
به هیچ سرویس لریو ارسال نمی‌شود.
